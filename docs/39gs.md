# 39gs compatibility contract

The 39gs profile is a non-negotiable first-class target.

## Historical baseline

Use **HPGCC 1.1-p1 with 39G support**, not HPGCC 2.0 SP2, as the compatibility baseline for 39g+/39gs/40gs packaging.

The historical package combines two distinct pieces:

### Native ARM payload

- HPGCC MMU loader/runtime contract;
- `MMUloader.o`;
- `MMUglobals.o`;
- `MMUld.script`;
- HP-string conversion.

### HP39 shell/package

- `hp2aplet`;
- ARMToolbox39 / library 275;
- `LIB275L.L39`;
- `apletcode.bin`;
- `apletepilog.bin`;
- `blank.gro`;
- HP39 directory metadata.

Both parts matter. Keeping only the C compiler flags is insufficient.

## Hardware-proven modern baseline

The existing 39gsX work has already validated this hybrid build strategy on real hardware:

1. compile new application code with modern Clang:
   ```
   clang --target=arm-none-eabi -march=armv4t -marm ...
   ```
2. link with LLD and the original HPGCC `MMUloader.o` / `MMUglobals.o`;
3. use a minimally normalized `MMUld.script`;
4. convert the ELF using the retained HPGCC HP-string algorithm;
5. package it with the original HP39 aplet algorithm/assets, with host-only safety/portability fixes.

This is hpclang's golden compatibility path until a replacement is proven at least as compatible on hardware.

## Required linker normalization

The known-good modernized script performs only compatibility changes:

- remove implicit `STARTUP()/INPUT()` inclusion of the MMU objects and pass them explicitly;
- replace the old GNU-ld-specific:
  ```
  __data_start = . - 0x09000400 + __got_start;
  ```
  with:
  ```
  __data_start = LOADADDR(.got) + SIZEOF(.got);
  ```
- align the copied data tail to 4 bytes;
- discard `.ARM.exidx*` and `.ARM.extab*` for the historical copier.

## Host-side hp2aplet normalization

Keep the aplet-building algorithm intact. Modern host fixes are limited to ordinary portability/safety issues such as:

- bounding historical oversized `fgets` calls;
- using a sufficiently large path buffer;
- correcting `strlen`/format type mismatches;
- making the data path layout explicit;
- avoiding the historical duplicate `fclose`.

These changes are not calculator-format redesigns.

## ABI caveat

The original HPGCC compiler used:

```
-fPIC -mpic-register=r10 -msingle-pic-base
```

and the MMU loader/runtime sets up HPGCC's global-data model around that convention.

39gsX proves that modern freestanding Clang code can coexist with the old startup objects for its tested workloads. It does **not** yet prove that arbitrary source using every legacy `libhplib` / `libhpg` function can be recompiled or linked without an ABI bridge.

Before declaring full HPGCC source compatibility, hpclang needs tests covering:

- calls in both directions across old-GCC/new-Clang object boundaries;
- global/static data access;
- function pointers;
- struct passing/return;
- 64-bit integer helpers;
- soft-float calling convention;
- callbacks/interrupt-sensitive code;
- any old library routine that assumes `r10` is the PIC base.

## Regression rule

Any future work on HPGCC 2.0 or HPGCC3 must leave the 39gs profile buildable. Replacing the 1.1-p1 39G runtime with a later 49/50-only runtime is a regression unless separately proven on 39gs hardware.
